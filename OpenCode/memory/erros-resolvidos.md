# Histórico de Erros Resolvidos e Soluções

Este arquivo registra bugs, comportamentos inesperados e workarounds encontrados durante o ciclo de desenvolvimento da aplicação **Mapa Urbano**, servindo como base de conhecimento para evitar reincidências.

## Registros de Erros Resolvidos

### [ERR-001] Repositório de Histórico tipado incorretamente com a própria interface
- **Data**: 2026-11-12
- **Módulo / Camada**: Repository / JPA
- **Arquivos Afetados**: `src/main/java/v1/mapaurbano/repository/HistoricoStatusRepository.java`
- **Problema / Erro**: A inicialização do contexto do Spring Data JPA falhava por parâmetro genérico inválido de entidade.
- **Causa Raiz**: A interface foi declarada como `public interface HistoricoStatusRepository extends JpaRepository<HistoricoStatusRepository, Long>`, passando a própria interface do repositório no primeiro tipo genérico do `JpaRepository`.
- **Solução Aplicada**: O tipo genérico foi corrigido para a entidade correspondente: `JpaRepository<HistoricoStatus, Long>`.

---

### [ERR-002] Filtro JWT não injetado no contexto do Spring Security
- **Data**: 2026-11-12
- **Módulo / Camada**: Segurança / Config
- **Arquivos Afetados**: `src/main/java/v1/mapaurbano/config/JwtAuthFilter.java`
- **Problema / Erro**: A classe `SecurityConfig` não conseguia injetar a dependência `jwtAuthFilter` via construtor, gerando falha de criação de bean na inicialização do Spring Boot.
- **Causa Raiz**: A classe `JwtAuthFilter` herdava de `OncePerRequestFilter`, mas não possuía a anotação `@Component`, não sendo gerenciada pelo Spring Container.
- **Solução Aplicada**: Adicionada a anotação `@Component` sobre a definição da classe `JwtAuthFilter`.

### [ERR-003] Erro de persistência de ID na tabela `usuario` com `GenerationType.IDENTITY`
- **Data**: 2026-11-12
- **Módulo / Camada**: Banco de Dados / Migrações Flyway
- **Arquivos Afetados**:
  - `src/main/resources/db/migration/V1__criar_tabela_usuario.sql`
  - `src/main/resources/db/migration/V5__alterar_coluna_id_usuario.sql`
- **Problema / Erro**: Ao tentar persistir um novo usuário pelo Hibernate, ocorria falha indicando que o PostgreSQL esperava uma chave primária explicitamente fornecida ou sequence/identity.
- **Causa Raiz**: A migração inicial `V1` declarou a coluna como `id BIGINT PRIMARY KEY` sem `SERIAL` ou cláusula `IDENTITY`, enquanto a entidade `Usuario` mapeava `@GeneratedValue(strategy = GenerationType.IDENTITY)`.
- **Solução Aplicada**: Foi criada a migração `V5__alterar_coluna_id_usuario.sql` executando:
  ```sql
  ALTER TABLE usuario
  ALTER COLUMN id ADD GENERATED BY DEFAULT AS IDENTITY;
  ```

### [ERR-004] Incompatibilidade de porta e credenciais de banco no Docker Compose
- **Data**: 2026-11-12
- **Módulo / Camada**: Infraestrutura / Docker
- **Arquivos Afetados**: `docker-compose.yaml`
- **Problema / Erro**: O container da aplicação não conseguia se comunicar com o banco de dados e a porta exposta não respondia nas requisições HTTP na porta 8080.
- **Causa Raiz**:
  1. A variável `SPRING_DATASOURCE_URL` apontava para `jdbc:postgresql://postgres:5432/nome_do_banco` enquanto o banco criado no container era `mapaurbano`.
  2. O mapeamento de portas da aplicação estava como `8080:80`, enquanto o Spring Boot escuta nativamente na porta `8080`.
  3. A aplicação tentava subir antes que o PostgreSQL estivesse pronto para receber conexões.
- **Solução Aplicada**:
  - Corrigido o banco na URL para `jdbc:postgresql://postgres:5432/mapaurbano`.
  - Ajustado o mapeamento de portas para `8080:8080`.
  - Adicionado `healthcheck` com `pg_isready -U postgres` no serviço `postgres` e configurada a dependência na aplicação como `condition: service_healthy`.
